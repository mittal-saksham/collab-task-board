# Deploying to Render (free tier)

This deploys the whole app — Postgres + FastAPI backend + React frontend — from the
`render.yaml` blueprint in this repo. It's mostly clicking; budget ~15 minutes.

> Why Render? One platform hosts all three pieces (DB, web service, static site),
> it builds the backend from our `Dockerfile`, and it supports WebSockets — so the
> live-update feature keeps working. The free tier is enough for a portfolio demo.
> (Heads-up: free services **sleep after ~15 min idle**, so the first request after
> a pause takes ~30s to wake. Normal for free tier.)

---

## What's already wired for you

- **`backend/Dockerfile`** — builds the API and, on start, runs `alembic upgrade
  head` (creating all tables on the fresh DB) then launches uvicorn.
- **`render.yaml`** — a Blueprint that creates the DB, the API, and the frontend,
  and connects them:
  - The DB connection string → the API's `DATABASE_URL_OVERRIDE`.
  - A generated `SECRET_KEY` for the API (never in git).
  - `ALLOWED_ORIGIN_REGEX = https://.*\.onrender\.com` so the deployed frontend is
    allowed by CORS without hard-coding its URL.
  - The API's hostname → the frontend's `VITE_API_URL` (the app prepends `https://`
    and derives `wss://` for WebSockets automatically).

## Steps

1. **Push this repo to GitHub** (already done — it's at
   `github.com/mittal-saksham/collab-task-board`).

2. **Create a Render account** at <https://render.com> — "Sign up with GitHub" is
   easiest. Authorize Render to read the repo (a private repo is fine).

3. **New + → Blueprint.** Pick this repository. Render detects `render.yaml` and
   shows the three resources it will create (db, `taskboard-api`, `taskboard-web`).
   Click **Apply**.

4. **Wait for the first build** (~3–5 min). The API image builds, migrations run,
   and the static frontend builds. When all three are green, open the
   **`taskboard-web`** URL (e.g. `https://taskboard-web.onrender.com`).

5. **Sign up in the app** and create a board — you're live.

### Optional: enable the "Summarize board" AI feature
In the Render dashboard → `taskboard-api` → **Environment** → set
`ANTHROPIC_API_KEY` to your key (from <https://console.anthropic.com>) → save
(the service redeploys). Without it, the button returns a clean 503.

## Verify it works

- `https://taskboard-api.onrender.com/health` → `{"status":"ok","database":"connected"}`
- `https://taskboard-api.onrender.com/docs` → the interactive API docs.
- The frontend loads, signup works, and a change in one browser tab appears live in
  another (that's the WebSocket over `wss://`).

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Frontend loads but every API call fails (CORS error in console) | The frontend origin isn't `*.onrender.com` (custom domain?) — add it to the API's `ALLOWED_ORIGINS` env var (comma-separated). |
| API won't start, logs mention the database | The DB wasn't ready on first boot. Just **Manual Deploy → Deploy latest** on the API once the DB is green. |
| Login works but live updates don't | Confirm the frontend is `https://` (so WebSockets use `wss://`); mixed `ws://` from an `https://` page is blocked by browsers. |
| First request hangs ~30s | Free service woke from sleep. Normal. |

---

## Notes

- **Secrets stay out of git.** `SECRET_KEY` is generated by Render; `ANTHROPIC_API_KEY`
  is pasted into the dashboard. Your local `.env` is never deployed.
- **Local dev is unchanged** — none of this affects `docker compose up` +
  `uvicorn` + `npm run dev`. The config falls back to the `POSTGRES_*` values and
  `localhost` CORS when the production env vars aren't set.
